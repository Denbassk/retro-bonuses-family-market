# Эталоны BigQuery и метод сверки

## Таблицы-эталоны Торгсофт

- `torgsoft_incoming_ref_2026` — приходы, 58 217 строк, документный уровень,
  только 2026. Сумма закупки в `amount` (не amount_purchase). Покрытие 02.01-31.08.
- `torgsoft_outgoing_ref` — возвраты, 8 205 строк, все годы. Есть флаги
  `is_prosrok` и `is_internal`, которых нет у нас. Продлён до 31.08.
- `torgsoft_sales_ref` — продажи, 1 765 568 строк. Используется для правил
  с `income_source=torgsoft_ref` (Арсенал ПК Шейк).

## Метод

Эталон приходов документный (58 тыс.), наша таблица построчная (440 888).
Сравнивать только агрегаты и `COUNT(DISTINCT doc_number)`.
Эталон хранит одну поставку ДВАЖДЫ — под коротким внутренним и длинным внешним
номером. Несовпавшие документы гасить парой (дата + сумма) среди уже совпавших,
и только остаток считать дырой (`find_bq_gaps.py`).
Межпоставщикский вердикт только при совпадении doc_number И суммы; совпадение
одной суммы у другого поставщика = MISSING (круглые суммы кратны упаковке,
коллизии на 60 тыс. документов неизбежны).
Джойнить по каноническому поставщику через `supplier_aliases`, не по сырой строке
`supplier` — иначе переименования дают зеркальные ложные дыры.

## Установленная картина расхождений

- Июль: у нас БОЛЬШЕ документов — это неполнота эталона (20.07: эталон 58 док
  против наших 123), не наша ошибка.
- Август: у нас меньше ровным слоем во все дни, обреза по дате нет; отсутствует
  подмножество поставщиков, крупнейший — Імператорська 275 док против 394.
- Возвраты: база «всё подряд», is_internal пустой, is_prosrok снимает 592 тыс.
  (вопрос слоя правил, не данных).
- Сбой загрузки 29-30.07.2026 перезалит, дыра закрыта.
- Остаток принят: MISSING 7 док / 13 235,50 (из них Оболонь 9 104,62 не трогаем),
  DATE_SHIFT 6 док / 20 459,98 (важно только совпадение МЕСЯЦА).

## Прочие справочники BQ

`supplier_mapping` (156) incoming_supplier -> matrix_supplier — готовый источник
недостающих алиасов, не используется. `supplier_aliases` в BQ (14) — отдельная от
одноимённой в Supabase, риск расхождения. `supplier_conditions` (105) — старый срез
условий, третий источник истины по процентам, как рабочий не годится.
`store_canon` (49) / `store_mapping` (43) — канонизация магазинов.
`turnover_monthly` — покрытие ТТ для Маршалл Табако.
Шум: около 20 таблиц *_backup_*, *_bak_*, transfer_pack_v5/v6 — в расчёте не участвуют.
